# テストと実機確認

[開発ガイド](development.md)の環境で実行します。成功件数の履歴を文書に転記せず、対象コミットのCI・コマンドの終了結果を確認します。

## 自動テスト

初回は固定版ブラウザを取得し、その後は一括確認を実行します。

```bash
bun run test:install
bun run check
```

依存を変更・取り込んだ場合は `bun run check:dependencies` も実行します。ブラウザテストだけ実行する場合は先に `bun run build` が必要です。実行中のテストとビルドは重ねません。

| 対象 | 主な確認 |
| --- | --- |
| 出題・進行 | 1回／3回、繰り返し、戻る、設定変更、区切り、終了後の操作、認識なしへの復帰 |
| 非同期処理 | 中断、遅い結果と履歴の対応、キューの置換、タイムアウト、資源の解放 |
| 保存 | 一時・保存録音の容量上限、削除の連動、バックアップ往復、不正形式の拒否、復元の保全 |
| 画面 | 設定・音選び・図解・履歴、フォーカス、外側クリック、ショートカット、主要操作位置 |
| 音声の受け渡し | 模擬音声の録音・末尾保持、ブラウザ認識へ渡す音声・無音・サンプルレート |
| 表示 | 同じ認識文字の更新、見本・録音のスペクトル保持と解除、狭い画面・動きを減らす設定 |
| 同梱資源 | 教材・音声マニフェスト・全ファイルのOggヘッダーとSHA-256、ライセンス生成漏れ |

通常CIは認識サービス・マイクを模擬し、大きな認識モデルを取得しません。音声ファイルの整合性、模擬音声の周波数、画面操作の成功から、実際の発音・認識精度・聞き取りやすさを推定しません。

文書だけの変更はリンク・記述・差分を確認します。音声の出典を変更した場合は `bun run generate:licenses` と `bun run check:licenses` で同梱ページも揃えます。

## 実モデルの接続を確認する

モデルや推論処理を変更した場合に、必要なモデルだけ明示的に取得します。ビルド後、次のサーバーを起動したまま、別ターミナルでスモークテストを実行します。

```bash
bun run build
bun --bun vite preview --port 4174
```

```bash
node scripts/smoke-models.mjs
# モデル・処理方式を絞る例
SMOKE_MODELS=small,kotoba node scripts/smoke-models.mjs
SMOKE_MODELS=cohere SMOKE_DEVICE=webgpu node scripts/smoke-models.mjs
```

既定はTiny／Base・WASMです。`SMOKE_URL` で確認先を変更できます。入力は無音1秒で、取得・前処理・推論の接続確認に限ります。このスクリプトのWebGPU指定はソフトウェアGPUを使うため、実GPUの検証を代替しません。生成された文字は精度評価に使いません。

## 実機で確認する範囲

ホストのEdge／Chromeで、変更に関係する項目をまとめて確認します。録音データの提出や、音声機器・GPUのコンテナ転送は不要です。

| 変更箇所 | 確認すること |
| --- | --- |
| 見本音声 | 声ごとの読み・アクセント・音量・速度、1回／3回再生、頭や末尾の聞こえ方 |
| 録音・音声経路 | マイク許可・選択、Bluetooth等の出力、無音終了、途中停止、聞き返し |
| 認識 | 日本語の1音・無意味2音・単語を分けて確認。言い直し・無音・違う音も試す |
| モデル・WebGPU | 取得失敗からの復帰、切り替え、長時間の処理速度・メモリ、停止 |
| スペクトル | 実際の見本・録音・マイクへの追従、停止後の比較、お題や声の変更時の解除 |
| 配信・対応端末 | 公開URLでの音声取得・マイク・連続再生。画面幅の確認と端末の音声動作は区別 |

実サービスはブラウザや提供状況で結果が変わります。認識精度を比較するときはモデル・ブラウザの版、音の種類、試行条件を揃えます。VOICEVOX等の収録見本を認識テストへ流しません。

スマートフォンの音声動作、モデルごとの日本語短音の精度、長時間の実GPU動作を網羅的に確認済みとはしていません。発音図解も専門家の監修・臨床的な有効性の検証とは別です。
